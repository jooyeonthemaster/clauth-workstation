# 실제 컴퓨터 인수 검사

가상 데이터 테스트와 실제 Claude 인증 흐름을 구분합니다. 다음 항목을 확인하기 전에는 해당 환경을 완전 검증했다고 표시하지 않습니다.

| 항목 | Windows x64 | macOS Intel | macOS ARM |
|---|---|---|---|
| 가상 데이터·HTTP·감독 로직 | CI 결과 확인 | CI 결과 확인 | CI 결과 확인 |
| 0.17.0 바이너리 해시·실행 | CI 결과 확인 | CI 결과 확인 | CI 결과 확인 |
| 실제 계정 2개 이상 로그인 | 미검증 | 미검증 | 미검증 |
| 전환 후 실제 요청의 계정 확인 | 미검증 | 미검증 | 미검증 |
| 사용량 임계 전환 중 대화 유지 | 미검증 | 미검증 | 미검증 |
| 토큰 갱신 경계·재로그인 | 미검증 | 미검증 | 미검증 |
| VS Code 확장 패널의 기존 대화 | 미검증 | 미검증 | 미검증 |
| 컴퓨터 재로그인 후 자동 실행 | 미검증 | 미검증 | 미검증 |

1. `doctor`에서 엔진 해시, 심볼릭 링크 권한, 기존 작업 충돌을 확인합니다.
2. 각 프로필이 의도한 계정인지 로그인 승인 화면에서 확인합니다. 정상 계정 두 개가 체인에 있어야 합니다.
3. 서비스를 설치하고 모니터에서 상태가 최신인지, 인증 실패나 빠진 프로필이 없는지 확인합니다.
4. 모니터의 기본 계정 전환 후 새로 여는 일반 Claude 세션이 실제 대상 계정을 사용하는지 확인합니다. 따로 `node src/cli.mjs start main`으로 연 관리 세션은 자신의 체인을 따릅니다. 이 세션의 임계치 fallback 후 실제 요청 계정을 별도로 확인합니다. 기본 계정 버튼은 기존 관리 세션을 강제로 이동시키지 않습니다. 단순히 `activeProfile`이 바뀐 것은 충분하지 않습니다.
5. 한도 초과 시 모든 후보가 막혔다는 안내가 나타나고, 사용 가능한 후보가 있을 때 전환이 이어지는지 확인합니다. 테스트를 위해 일부러 많은 토큰을 소모하지 않습니다.
6. 수동 로그인/갱신으로 live 체인이 달라졌을 때 새 토큰을 오래된 것으로 덮어쓰지 않고 적절히 대기·거부하는지 확인합니다.
7. macOS에서는 처음 Keychain 접근 승인을 완료하고 잠금/해제 후에도 재검사합니다.
8. 로그아웃·로그인 후 서비스가 한 개만 실행되고 모니터가 열리는지 확인합니다. Windows에 콘솔 창이 반복해서 깜빡이지 않아야 합니다.

VS Code 확장 패널은 현재 검증된 fallback 진입점이 아닙니다. 공식 [VS Code 설정](https://code.claude.com/docs/en/vs-code)의 `claudeProcessWrapper` 연계는 별도 구현과 실제 통합 검증이 필요합니다. 현재 패키지는 확장 실행 파일이나 VS Code 설정을 바꾸지 않습니다.
