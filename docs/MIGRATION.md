# 기존 PC 이전

이 패키지의 `setup`은 기존 설치를 자동 이전하지 않습니다. 기존 PC에서는 0.14 엔진·복구 작업이 실제로 인증을 유지하고 있어, 확인 없이 동시에 바꾸면 로그인 충돌을 재현할 수 있습니다.

먼저 `npm run monitor -- --port 47822`로 새 화면을 읽기 전용으로 확인합니다. 이 실행은 계정 전환·복구·데몬 시작을 수행하지 않습니다.

실제 이전은 새 컴퓨터의 [ACCEPTANCE.md](ACCEPTANCE.md)를 통과한 뒤 진행합니다.

1. 진행 중인 Claude 작업을 끝냅니다. 기존 자동화와 clauth 데몬을 중지합니다.
2. 기존 시작프로그램, 예약 작업 설정, `.clauth` 및 필요한 `.claude` 설정을 **이 PC에만** 백업합니다. 이 백업은 인증 정보를 포함하므로 저장소 밖에 둡니다. 다른 컴퓨터로 인증 파일을 복사하지 않습니다.
3. 기존 `clauth-*` 작업과 Startup의 `clauth-daemon.vbs`를 비활성화합니다. 다른 프로그램의 예약 작업은 건드리지 않습니다.
4. 원래 `.clauth`를 별도 로컬 백업 디렉터리로 보관해 새 경로를 비웁니다. 기존 인증 파일과 세션 복구는 수동으로 검토합니다.
5. `npm run setup`으로 새 엔진·설정을 만들고 각 계정을 다시 로그인합니다. 로그인 후 기대 이메일과 계정 별칭을 직접 확인합니다.
6. `doctor` → 서비스 설치 → 실제 전환 → 새 로그인 세션 → 재로그인/재부팅 순으로 확인합니다.

자동화가 실패하면 새 서비스와 새 데몬을 먼저 중지하고 이전 설정·시작 항목을 복구합니다. 오래된 OAuth 토큰은 이미 갱신되었을 수 있으므로 과거 토큰 백업을 맹목적으로 덮어쓰면 안 됩니다. 필요하면 해당 계정을 다시 로그인합니다.

정책 재적용·새 계정 등록은 컴패니언 서비스와 엔진이 꺼져 있는 정비 시간에 수행합니다. 구성 파일의 원자적 교체는 다른 프로세스와의 트랜잭션 잠금과 같지 않습니다.
